# Knowledge Harvest MVP: capability transfer

Updated November 6, 2026. Prove that one employee can handle one defined class of work with less unnecessary founder intervention while maintaining agreed quality and appropriate escalation.

## Available now

The [Capability Transfer Framework](capability-transfer/README.md) supplies a manual workflow, reusable workbook, diagnosis prompts, fictional MSP example, measurement rules, product specification, and implementation backlog. These are pilot materials, not validated outcome claims.

The existing code supports recording and retrieval: React UI, Express API, PostgreSQL metadata, and local uploaded files in the current server implementation. S3 appears in development configuration and earlier plans but is not integrated in the inspected server. The four-screen case workflow is not implemented.

## Pilot scope

- One recurring dependency, defined task boundaries, named participants, and baseline evidence.
- Diagnose capability, authority, access, capacity, expectations, and other causes before selecting an intervention.
- Expert-approved aid and unfamiliar practice where needed; a management intervention may be sufficient.
- Explicit authority, time, access, opportunity, feedback, and recovery plan for actual work.
- Human-reviewed evidence separating practice, supported live work, and observed independence.
- Compare avoidable escalations, decision quality, founder and total support time, rework, and delayed defects; record delivery effort.

Agree case-specific evidence requirements and quality guardrails before intervention. Recording counts, viewing time, and completion rates measure capture-tool usability, not capability transfer. A pilot can validly conclude insufficient evidence, revise, pause, or stop.

## First software slices

Implement cases and eligible-opportunity logging, then diagnosis/conditions/results. Use fictional data until private access controls cover records, uploads, exports, and deletions. Extend guided capture, approved aid versions, practice, and follow-up after manual delivery shows what is useful. See the [implementation backlog](capability-transfer/implementation-backlog.md) for acceptance checks.

## Deferred

Multi-client deployment, autonomous AI decisions, automatic competence scoring, broad LMS functionality, and microservices are outside this pilot. AI drafting is optional and requires expert review. No fixed schedule or performance improvement is promised.

The [historical recording MVP](archive/recording-mvp-definition.md) remains available as context.
