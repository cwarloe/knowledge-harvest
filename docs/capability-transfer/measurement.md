# Measurement and evidence rules

Agree definitions before collecting baseline data. This is a descriptive pilot, not proof that the intervention caused all observed changes.

## Count opportunities, not just escalations

An **eligible opportunity** is one work item within the pre-agreed task boundary. Count it once, even if it produces several messages; sum founder handling minutes for that item. Keep outside-scope work separately. Baseline and follow-up must use the same inclusion rules, or disclose the change and avoid direct comparison.

| Measure | Definition | Interpretation |
| --- | --- | --- |
| Avoidable escalation rate | Reviewer-confirmed avoidable escalations / all eligible opportunities | Lower may indicate less unnecessary dependency |
| Missed-required escalation rate | Eligible opportunities where required escalation was missed / all eligible opportunities | Quality guardrail; also report the number of cases requiring escalation |
| Decision quality | Eligible outputs meeting the agreed standard / eligible outputs actually reviewed | Report review coverage and reasons for unreviewed outputs |
| Independent performance | Reviewed eligible outputs meeting the standard, completed within authority without unplanned human help / reviewed eligible outputs | Approved job aids are allowed; disclose actual assistance |
| Founder burden | Total founder handling/review minutes / all eligible opportunities | Include asynchronous correction and later rework |
| Total support burden | Founder + other expert/supervisor/peer support minutes / all eligible opportunities | Detect shifting work away from the founder without reducing total burden |
| Rework | Number of reviewed outputs requiring correction; include delayed callbacks | Track severity and attributable case IDs |
| Time to independence | Calendar duration from agreed start to scope-limited human acceptance | Report opportunity count; no evidence is not a fast success |

Always show raw counts and denominators alongside rates. A zero denominator is **not available**, not 0%. Unknown escalation classifications remain visible and do not become avoidable by default. Report the classified fraction. Missing quality reviews are unknown, not passes. Do not silently drop difficult cases or unsuccessful attempts.

## Classify escalation carefully

- **Appropriate:** a required boundary, genuine uncertainty, risk, or authority limit warranted escalation.
- **Avoidable:** with approved aids, authority, and available information, the agreed task should have been independently manageable.
- **Missed-required:** employee acted without escalating when the agreed boundary required it.
- **Disputed/unknown:** reviewers disagree or evidence is missing; record and investigate.

The reviewer records the reason and source rule. If management expectations were ambiguous, diagnose that ambiguity before labeling employee behavior avoidable.

## Evidence status is distinct from workflow stage

| Status | Required evidence | What it does not establish |
| --- | --- | --- |
| Not assessed | No reviewed attempts | No competence conclusion |
| Demonstrated in practice | Reviewed unfamiliar practice attempts with reasoning and assistance recorded | Workplace performance |
| Supported live application | Actual work reviewed; human coaching/help recorded | Independence |
| Observed independent performance | Real work within scope and authority, acceptable quality, permitted aids disclosed, no unplanned human help; human reviewer accepts the agreed volume/variety/window | Universal competence, permanence, or causal proof |
| Insufficient evidence | Missing, contradictory, too narrow, or stale evidence; reason recorded | Failure or success by default |

No universal pass mark or fixed number of cases is asserted. Agree an evidence requirement appropriate to the task before intervening. A delayed review tests whether application persists. If no suitable work occurs, extend or pause and record **insufficient evidence**. One critical error triggers the pre-agreed hold/review rule even if aggregate rates improve.

## Review decision

Compare task mix, workload, staffing, authority, and case severity across windows. Report alternative explanations. A good pilot conclusion reads: “Across these reviewed cases, under these conditions, performance met this standard with this assistance.” Report delivery effort separately from recurring support savings; do not translate founder time into revenue without evidence that the time was productively redeployed.

Continue when the pre-agreed outcome improves with quality maintained and effort acceptable. Revise when a diagnosis or aid is wrong. Pause when opportunities or required support are absent. Stop when costs or harm outweigh likely benefit. The owner records the decision; software never infers it from a single dashboard number.
